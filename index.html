Jua Kali API — Organ Donation App Consumer Contract (1.0.0)

Download OpenAPI specification:

Scoped specifically to the interconnect relationship with the organ donation app (per API_NEEDS.md / ENDPOINT_LIST.md). This is NOT a full document of Jua Kali's entire API surface — internal-only endpoints (auth, user management, reviews, the general booking list/create used by Jua Kali's own frontend) are intentionally out of scope, since this consumer never calls them. All paths below are implemented in server/routes/artisans.js and server/routes/bookings.js.

Return verified artisans and their services

Implemented in server/routes/artisans.js. Satisfies: "The organ donation app needs to read verified artisans and their services in order to identify workers who can provide services when the hospital needs them." Also satisfies the pricing need (rate is included per artisan) without a separate /services endpoint — see ENDPOINT_LIST.md's note on why a standalone services catalog would misrepresent pricing.

string
Example: skill=Plumbing

boolean

Return only a booking's status

Implemented in server/routes/bookings.js. Kept as its own nested sub-resource (the state genuinely belongs to one specific booking, same reasoning as /users/{id}/tasks from the lecture), rather than requiring the organ donation app to fetch the whole booking record just to check accept/decline status. Satisfies: "The organ donation app needs to read actions taken by the artisan (accepted or declined) in order to identify workers who have agreed to perform a particular service."

Update only a booking's status

Implemented in server/routes/bookings.js. Requires artisan auth — this is the artisan's own accept/decline/complete action, not something the external consumer performs. This is now the one real way to change a booking's status; the old general PATCH /api/bookings/{id} was removed to avoid two routes doing the same job.
